## 3차 — 최애(찜한 아이돌) 기능 추가 시 발견

PR 생성 후 최애 기능(`onlyFavoriteGroups` 필터 + 홈 섹션)을 얹으면서 나온 것들.

| 발견 | 조치 | 근거 |
|---|---|---|
| **검색어가 없을 때 최애 필터가 통째로 사라짐** | `resolveKeywordMatches` 가 조건을 새로 만들지 않고 키워드 필드만 갈아끼우도록 수정 | 정규화 결과가 null 이면 3-인자 생성자로 조건을 재생성해 `favoriteGroupIds` 를 버렸다. 즉 **"최애만 보기"가 전체 분철을 반환**하는 상태. 단위 테스트가 잡았다 |
| 최애 0개를 "필터 없음"과 같은 값으로 접으면 전체가 노출됨 | 적용 여부를 id 목록이 아니라 `onlyFavoriteGroups` 플래그로 분리하고, 0개면 서비스가 조회 전에 빈 결과로 단축 | 처음엔 `favoriteGroupIds != NO_MATCH` 참조 비교로 판정했는데, 빈 목록도 NO_MATCH 로 접혀 필터가 꺼졌다 |
| 인기 그룹이 비면 전체 188개 그룹이 홈 레일에 노출 | `requestPopularGroups({ fallbackToAllGroups: false })` 로 홈에서만 폴백 차단 | 기존 폴백은 검색 화면의 "인기 아티스트"가 비어 보이지 않게 하려던 것. 홈 레일 소스로 쓰면서 **분철 없는 그룹 수백 개**가 노출되는 경로가 됐다 |
| 최애만 남기면 새 그룹 발견이 막힘 | 레일을 **최애 먼저 → 인기 이어붙이기**(중복 제거)로 | 최애 등록 순간 인기 그룹이 사라지던 구성 |
| 최애 전부 해제해도 섹션이 남음 | 섹션 노출 판정을 `favorited !== false` 인 항목 수로 | 해제 시 레일에서 항목을 빼지 않고 플래그만 내리는 기존 동작 때문 |

### 브라우저 검증에서 확인하지 못한 것

- **하트 토글로 최애 추가/해제 → 섹션 즉시 갱신**: 로컬 검증에 쓴 수동 발급 토큰에는 refresh 쿠키가 없어 `getFreshAccessToken()` 이 `/auth/reissue` 401 에서 멈춘다. 토글 핸들러가 그 지점에서 조용히 중단돼 요청 자체가 나가지 않았다. **테스트 하네스 제약이며 실제 로그인 사용자에겐 해당하지 않는다.** 대신 API 로 최애를 해제한 뒤 재조회해 레일 순서와 섹션 건수(6 → 4)가 따라오는 것은 확인했다.
- 관련해 짚어둘 점: 해당 핸들러는 `getFreshAccessToken()` 이 실패하면 **아무 피드백 없이 중단**된다(기존 코드). 이번 범위 밖이라 두었으나 개선 여지가 있다.

## 4차 — 최애 하트 409 제보 (사용자 발견)

**증상**: 아이돌 목록에서 하트를 눌렀는데 찜이 안 되고 conflict 가 난다.

**원인**: `addFavoriteGroup` 이 **409 를 전부 "이미 등록됨"으로 처리**하고 있었다.

```ts
if (response.status === 409) {
  return { alreadyExists: true };   // GRP-005(5개 한도 초과)도 여기로 빠진다
}
```

서버의 409 는 두 가지이고 처리가 정반대다.

| 코드 | 의미 | 올바른 처리 |
|---|---|---|
| `GRP-003` | 이미 최애로 등록됨 | 원하는 상태가 이미 만족 → **성공으로 접는다** |
| `GRP-005` | 최애 5개 한도 초과 | 등록 **안 됐다** → 롤백 + 이유 표시 |

둘을 같게 다루면 한도 초과인데 `/artists` 화면이 하트를 켜고 카운트가 `6/5` 가 된다. 서버엔 저장되지 않았으니
새로고침하면 풀린다 — "눌러도 찜이 안 된다" 는 제보와 정확히 일치한다. 홈 레일은 반환값을 아예 무시해
더 조용히 실패했다.

**조치**

| 조치 | 내용 |
|---|---|
| 409 를 코드로 분기 | `GRP-003` 만 성공 처리, 나머지는 서버 메시지로 throw |
| 클라이언트 한도 가드 | 홈 레일·`/artists` 모두 6번째 클릭을 왕복 없이 막고 이유 표시 (레일엔 개수 표시가 없어 눌러보고서야 알게 됐다) |

**검증**: 최애 5개 상태에서 6번째 하트 클릭 → 하트 유지, `5/5` 유지, **POST 요청 자체가 나가지 않음**.
수정 전에는 하트가 켜지고 `6/5` 가 됐다가 새로고침 시 원복됐다.

**왜 이번에 드러났나**: `favoriteArtists` 플래그를 켜면서 지금까지 홈으로 리다이렉트되던 `/artists` 화면이
처음 열렸다. 플래그를 켤 때는 그 뒤에 있던 화면 전체가 새 QA 대상이 된다는 걸 이번에 놓쳤다.
